Промт: Разработка мини-приложения Telegram «Услуги рядом»
1. Роль и задача
Ты — senior fullstack-разработчик и архитектор мини-приложений для Telegram (TMA). Твоя задача — спроектировать и создать мини-приложение «Услуги рядом», которое объединяет исполнителей (мастеров, фрилансеров, специалистов) и клиентов внутри экосистемы Telegram.

Приложение должно быть реализовано как Telegram Mini App (WebView), запускаемое через inline-кнопку или меню бота, с обязательной авторизацией через Telegram Web App SDK.

2. Общая архитектура системы
Система состоит из трёх связанных компонентов:

Telegram Bot — точка входа, авторизация, доставка push-уведомлений и напоминаний.
Frontend (Mini App) — React-приложение (SPA), работающее внутри Telegram WebView. Адаптивно под iOS/Android/ Desktop.
Backend + БД — REST API и WebSocket для чата, хранение данных.
Рекомендуемый стек:

Frontend: React 18+, TypeScript, Vite, React Router v6, telegram-web-app.js SDK, @twa-dev/sdk, UI-kit: @twa-dev/ui или radix-ui + tailwindcss с переменными Telegram (var(--tg-theme-bg-color) и т.д.).
Backend: Node.js + NestJS (или Python + FastAPI).
Database: PostgreSQL 15 (основная база) + Redis (кеши, сессии, очередь уведомлений).
Хранилище: S3-совместимое облако (AWS / Yandex Cloud / Selectel) для фото.
Карты: Яндекс.Карты JS API или Leaflet (OpenStreetMap) для отображения и геолокации.
Платежи: API ЮKassa (или Stripe для международного рынка). На MVP можно оставить «оплату наличными/переводом».
Очередь сообщений: BullMQ (Redis) для отложенных уведомлений.
3. Модель данных (основные сущности)
Спроектируй БД со следующими таблицами/коллекциями:

Сущность	Ключевые поля
users	id, telegram_id (уникальный), username, first_name, last_name, phone, avatar_url, role (client/worker), geo_lat, geo_lon, created_at
categories	id, name, emoji_icon, sort_order, parent_id (для подкатегорий)
worker_profiles	id, user_id, description, category_id, address, work_radius_km, rating, total_orders, is_verified, balance
services	id, worker_id, title, description, category_id, price, duration_minutes, photos[] (URL из S3), is_active, created_at
schedules	id, worker_id, date (или day_of_week для шаблона), start_time, end_time, is_working, slot_duration_minutes
bookings	id, client_id, worker_id, service_id, booking_datetime, status (pending / confirmed / completed / cancelled), price, address, comment, created_at
reviews	id, booking_id, from_user_id, to_user_id, rating (1-5), text, is_moderated, created_at
promotions	id, worker_id, service_id, discount_percent/fixed_amount, valid_from, valid_to, usage_limit
group_orders	id, client_id, service_id, event_date, guests_count, budget, status, offers[] (JSON отклики работников)
4. Функциональные модули
4.1. Авторизация и старт
При нажатии кнопки «Запустить приложение» бот передаёт в Mini App initData.
Frontend отправляет initData на Backend (POST /auth/verify).
Backend валидирует HMAC-подпись Telegram. Если ок — выпускает JWT-пары (access + refresh) или создаёт сессию в Redis.
Если пользователь новый — автоматическая регистрация. Запросить геолокацию через navigator.geolocation (с фолбэком на ручной ввод адреса).
4.2. Личный кабинет исполнителя (Worker Dashboard)
Раздел доступен при переключении роли (или автоматически, если у пользователя есть worker_profiles).

Функции:

Профиль: Редактирование описания, выбор категории, загрузка аватара, указание адреса и радиуса выезда.
Мои услуги: CRUD. Для каждой услуги: название, описание (до 1000 символов), фото-примеры (до 10 шт., сжатие на клиенте до 1280px, WebP), цена (руб./долл.), длительность.
Расписание:
Шаблон недели (пн-вс, часы работы).
Возможность блокировать конкретные даты/часы (через календарь).
Автоматическая генерация свободных слотов на основе длительности услуги и существующих броней.
Заказы (Bookings):
Список входящих заявок со статусами.
Кнопки: Подтвердить / Отклонить / Перенести.
Карточка заказа: дата, услуга, клиент (имя из Telegram), адрес, комментарий.
Статистика:
Выполнено заказов за месяц/всё время.
Выручка.
Средний рейтинг (звёзды + прогресс-бар).
График загруженности (Recharts или Chart.js).
Акции: Создание скидки на конкретную услугу или всё портфолио. Отображение старой/новой цены.
4.3. Поиск и бронирование (Client Flow)
Главный экран клиента:

Верхний поиск по ключевым словам (ILike по services.title и worker_profiles.description).
Горизонтальный скролл категорий с иконками.
Переключатель вида: Список / Карта.
Фильтры (нижний шторка/bottom sheet): категория, цена (min/max), рейтинг (от 4.0+), дата/время.
Кнопка «Рядом со мной»: запрашивает navigator.geolocation, сортирует исполнителей по формуле Haversine (ближайшие первыми) или показывает на карте круговой радиус.
Карточка исполнителя:

Фото/видео работы (Swipeable галерея).
Имя, рейтинг, отзывы (количество).
Описание, адрес, рабочие часы.
Таблица услуг с ценами.
Визуальный календарь: клиент выбирает дату → подгружаются свободные слоты (GET /workers/:id/slots?date=YYYY-MM-DD). Выбор слота → экран подтверждения.
Кнопка «Записаться». При нажатии — предоплата (если подключена) или моментальное создание заявки POST /bookings.
Мои записи (Клиент):

Список предстоящих и прошедших.
Кнопка отмены (за N часов до визита).
Кнопка «Оставить отзыв» (доступна только после completed).
4.4. Уведомления (через Telegram Bot API)
Реализовать через отдельный worker/очередь. Использовать метод sendMessage с клавиатурами.

Событие	Получатель	Содержание
Новая запись	Исполнитель	«У вас новая заявка на [Услуга], [Дата]. Подтвердить?» + кнопки
Подтверждение	Клиент	«Мастер подтвердил вашу запись на [Дата]»
Напоминание	Клиент	За 24 часа и за 1 час до визита
Отмена	Контрагент	«К сожалению, запись отменена»
Отзыв	Исполнитель	«О вас оставили отзыв: ⭐️ 5»
Акция	Подписчики	«Мастер [Имя] запустил скидку 20%»
4.5. Рейтинги и отзывы
После завершения услуги (исполнитель нажимает «Выполнено» или автоматом через 24ч) клиент получает ссылку на форму отзыва в Mini App.
Оценка: 5 звёзд + текстовый комментарий.
Рейтинг исполнителя — среднее арифметическое всех оценок, хранится в worker_profiles.rating.
Возможность пожаловаться на отзыв (для модерации).
4.6. Чат и коммуникация
Вариант A (MVP): Кнопка «Написать мастеру» открывает личные сообщения Telegram через tg.openTelegramLink('https://t.me/username').
Вариант B (встроенный): WebSocket-чат внутри Mini App. Хранить историю в таблице messages. Уведомления о новых сообщениях через бота.
4.7. Групповые заказы (MVP-2)
Клиент создаёт заявку на мероприятие: дата, количество гостей, бюджет, описание.
Заявка публикуется в ленте (или рассылается подходящим исполнителям категории).
Исполнители отправляют предложения (цена, условия).
Клиент выбирает лучшее offer.
4.8. Социальные функции
Поделиться: кнопка shareURL (Telegram Share) на карточке исполнителя/услуги. Генерация startapp параметра с ID услуги (t.me/botname?startapp=service_123).
Рекомендации: алгоритм на основе последних просмотренных/забронированных категорий. Отображать в блоке «Вам может понадобиться» на главной.

7. Безопасность и ограничения
Обязательная проверка подписи initData на Backend перед любыми операциями.
Rate Limiting: не более 10 запросов в секунду с одного IP, не более 3 попыток бронирования в минуту.
Валидация загружаемых файлов: только изображения, max 5MB, проверка MIME-type, сканирование через ClamAV (опционально).
SQL-инъекции: использовать ORM (Prisma/TypeORM) с параметризованными запросами.
XSS: escape вывод пользовательского контента.

server/src/auth.ts
import crypto from 'crypto';
import jwt from 'jsonwebtoken';

export function verifyInitData(initData: string, botToken: string): boolean {
  const urlParams = new URLSearchParams(initData);
  const hash = urlParams.get('hash');
  if (!hash) return false;

  urlParams.delete('hash');
  const params: string[] = [];
  urlParams.sort();
  for (const [key, value] of urlParams.entries()) {
    params.push(`${key}=${value}`);
  }
  const dataCheckString = params.join('\n');
  const secret = crypto.createHmac('sha256', 'WebAppData').update(botToken).digest();
  const checkHash = crypto.createHmac('sha256', secret).update(dataCheckString).digest('hex');
  return hash === checkHash;
}

export function signJwt(payload: object) {
  return jwt.sign(payload, process.env.JWT_SECRET!, { expiresIn: '7d' });
}

export function verifyJwt(token: string) {
  try {
    return jwt.verify(token, process.env.JWT_SECRET!) as { userId: number; telegramId: string };
  } catch {
    return null;
  }
}

app.get('/api/services', async (req) => {
  const q = req.query as Record<string, string>;
  const lat = parseFloat(q.lat || '0');
  const lon = parseFloat(q.lon || '0');
  const radius = parseFloat(q.radius || '50'); // km
  const categoryId = q.categoryId ? parseInt(q.categoryId) : null;

  const services = await prisma.$queryRaw`
    SELECT s.id, s.title, s.description, s.price, s.duration, s.photos,
           u."firstName" as worker_name, wp.rating,
           (6371 * acos(
              cos(radians(${lat})) * cos(radians(u.lat)) *
              cos(radians(u.lon) - radians(${lon})) +
              sin(radians(${lat})) * sin(radians(u.lat))
           )) as distance
    FROM "Service" s
    JOIN "WorkerProfile" wp ON s."workerId" = wp.id
    JOIN "User" u ON wp."userId" = u.id
    WHERE s."isActive" = true
      AND u.lat IS NOT NULL AND u.lon IS NOT NULL
      ${categoryId ? Prisma.sql`AND s."categoryId" = ${categoryId}` : Prisma.empty}
    ORDER BY distance ASC NULLS LAST
    LIMIT 20
  `;

  return (services as any[]).filter((s) => !s.distance || s.distance < radius);
});

const API = 'http://localhost:4000/api';

function getToken() {
  return localStorage.getItem('jwt') || '';
}

async function fetcher(url: string, opts?: RequestInit) {
  const res = await fetch(`${API}${url}`, {
    ...opts,
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${getToken()}`,
      ...(opts?.headers || {}),
    },
  });
  if (!res.ok) throw new Error(await res.text());
  return res.json();
}

export const api = {
  auth: (initData: string) => fetcher('/auth/verify', { method: 'POST', body: JSON.stringify({ initData }) }),
  categories: () => fetcher('/categories'),
  services: (params?: { lat?: number; lon?: number; categoryId?: number; radius?: number }) => {
    const qs = new URLSearchParams();
    if (params?.lat) qs.set('lat', String(params.lat));
    if (params?.lon) qs.set('lon', String(params.lon));
    if (params?.categoryId) qs.set('categoryId', String(params.categoryId));
    if (params?.radius) qs.set('radius', String(params.radius));
    return fetcher(`/services?${qs}`);
  },
  bookings: (body: { serviceId: number; datetime: string }) =>
    fetcher('/bookings', { method: 'POST', body: JSON.stringify(body) }),
  myBookings: () => fetcher('/bookings/my'),
  workerMe: () => fetcher('/worker/me'),
  createService: (body: object) => fetcher('/worker/services', { method: 'POST', body: JSON.stringify(body) }),
};

  const [ready, setReady] = useState(false);

  useEffect(() => {
    const init = async () => {
      const initData = tg.initData;
      if (!initData) {
        alert('Откройте через Telegram');
        return;
      }
      try {
        const res = await fetch('http://localhost:4000/api/auth/verify', {

          headers: { 'Content-Type': 'application/json' },

          localStorage.setItem('jwt', data.token);
          localStorage.setItem('role', data.user.role);
          setReady(true);
        }

        console.error(e);
      }
    };
    init();
  }, []);

  if (!ready) return <div style={{ padding: 20 }}>Загрузка...</div>;

  const isWorker = localStorage.getItem('role') === 'WORKER';

  return (
    <BrowserRouter>
      <Routes>
        <Route element={<Layout isWorker={isWorker} />}>
          <Route path="/" element={<Home />} />
          <Route path="/service/:id" element={<ServiceDetail />} />
          {isWorker && <Route path="/cabinet" element={<WorkerCabinet />} />}
        </Route>
      </Routes>
    </BrowserRouter>
  );
}

import { useEffect, useState } from 'react';

export function Home() {
  const [services, setServices] = useState<Service[]>([]);
  const [categories, setCategories] = useState<Category[]>([]);
  const [catId, setCatId] = useState<number | undefined>();
  const [geo, setGeo] = useState<{ lat: number; lon: number } | null>(null);

  useEffect(() => {
    api.categories().then(setCategories);
    loadServices();
  }, []);

  const loadServices = async (params?: { lat?: number; lon?: number; categoryId?: number }) => {
    const data = await api.services(params);
    setServices(data);
  };

  const nearMe = () => {
    if (!navigator.geolocation) return alert('Геолокация недоступна');
    navigator.geolocation.getCurrentPosition(
      (pos) => {
        const { latitude, longitude } = pos.coords;
        setGeo({ lat: latitude, lon: longitude });
        loadServices({ lat: latitude, lon: longitude, categoryId: catId });
      },
      () => alert('Не удалось получить геолокацию')
    );
  };

  const filterCategory = (id?: number) => {
    setCatId(id);
    loadServices({ ...geo, categoryId: id });
  };

  const formatPrice = (p: number) => `${(p / 100).toFixed(0)} ₽`;

  return (
    <div>
      <div className="tags">
        <div className="tag" onClick={() => filterCategory(undefined)} style={{ cursor: 'pointer' }}>Все</div>

          </div>

Вот детальное архитектурно-техническое описание того, как реализуется проект «Услуги рядом» от нуля до продакшен-окружения. Это не повторение кода, а объяснение механики, инфраструктуры и инженерных решений.

1. Общая архитектура и точка входа
Приложение работает как Telegram Mini App (TMA) — это HTML5-страница, открываемая внутри нативного WebView Telegram. Пользователь взаимодействует с ботом через Inline-кнопку или Menu Button, которая передаёт initData (подписанные данные пользователя) в веб-приложение.

┌─────────────────┐ initData ┌──────────────┐ │ Telegram App │ ─────────────────►│ Frontend │ │ (WebView) │◄─────────────────│ (React/Vite)│ └─────────────────┘ JWT + JSON └──────┬───────┘ │ REST/WebSocket │ ┌─────────────────┐ HTTPS/WS ┌──────▼───────┐ │ Telegram Bot │◄─────────────────│ Backend │ │ (node- │ push-уведомл. │ (Fastify) │ │ telegraf) │ └──────┬───────┘ └─────────────────┘ │ │ ┌────────┴────────┐ │ PostgreSQL │ │ (основная) │ │ + PostGIS │ ├─────────────────┤ │ Redis (кеш/ │ │ сессии/очереди)│ ├─────────────────┤ │ S3 (фото) │ └─────────────────┘
2. Компоненты системы
2.1. Frontend (Mini App)
Среда исполнения: WebView Telegram (iOS WKWebView / Android WebView / Desktop Electron).

Технологический стек:

Vite — сборка. Критично, потому что нужен моментальный HMR для разработки и малый бандл для мобильных сетей.
React 18 + TypeScript. Архитектура — Feature-Sliced Design (FSD) или модульная:
pages/ — экраны (поиск, кабинет, карточка услуги).
entities/ — бизнес-сущности (Service, User, Booking).
shared/api/ — единый инстанс fetch с перехватчиком JWT.
Роутинг: react-router-dom в режиме HashRouter или BrowserRouter. В TMA лучше BrowserRouter, так как Telegram поддерживает History API.
UI: только нативные переменные темы Telegram (--tg-theme-*). Никаких собственных фиолетовых тем — иначе приложение выглядит чужеродно.
Telegram WebApp SDK: Скрипт telegram-web-app.js инжектит глобальный объект window.Telegram.WebApp. Через него приложение:

Сообщает Telegram, что готово (tg.ready()).
Запрашивает раскрытие на весь экран (tg.expand()).
Показывает нативный Confirm (tg.showConfirm) и Popup (tg.showPopup).
Закрывает приложение (tg.close()) после успешного бронирования.
Открывает счёт на оплату (tg.openInvoice), если подключены платежи Telegram.
2.2. Backend (API Gateway)
Fastify выбран вместо Express из-за:

Встроенной валидации через JSON Schema (скорость сериализации).
Системы Hooks (onRequest, preHandler) — удобно для middleware.
Скорости: в 2–3 раза выше пропускная способность на микросервисах.
Слоеная архитектура:

src/ ├── plugins/ # Регистрация CORS, JWT, Swagger ├── modules/ │ ├── auth/ # Верификация initData │ ├── user/ # Профиль, роли │ ├── worker/ # CRUD услуг, расписание │ ├── client/ # Поиск, бронирование │ └── booking/ # Логика слотов, статусы ├── integrations/ # Bot API, S3, Payment Provider └── common/ # Prisma Client, constants
3. База данных: проектирование и оптимизация
3.1. Выбор PostgreSQL + PostGIS
Для геопоиска «Рядом со мной» чистый Haversine на уровне JS/Prisma работает медленно на 100k+ записей. PostGIS расширение позволяет:

Хранить координаты в типе GEOGRAPHY(POINT, 4326).
Искать по индексу GIST с функцией ST_DWithin (поиск в радиусе метров).
Сортировать по ST_Distance без полного перебора.
Миграция для гео:

CREATE EXTENSION IF NOT EXISTS postgis;

ALTER TABLE "User" ADD COLUMN location GEOGRAPHY(POINT, 4326);
CREATE INDEX idx_user_location ON "User" USING GIST(location);
Запрос «Рядом» на SQL:

SELECT u.*, wp.rating,
       ST_Distance(u.location, ST_SetSRID(ST_MakePoint($1, $2), 4326)) as dist
FROM "User" u
JOIN "WorkerProfile" wp ON wp."userId" = u.id
WHERE ST_DWithin(u.location, ST_SetSRID(ST_MakePoint($1, $2), 4326), $3)
  AND u.role = 'WORKER'
ORDER BY dist;
3.2. Таблицы-связи и нормализация
Category — справочник. Поддержка parent_id для вложенности (например, «Красота» → «Маникюр»).
Schedules — таблица занятости. Каждая строка — один день одного мастера. Это позволяет гибко задавать нестандартные дни (отпуск, переносы).
Bookings — связь client_id → worker_id → service_id. Поле status управляется через state-machine: PENDING → CONFIRMED → COMPLETED. Обратных переходов нет.
3.3. Индексы производительности
CREATE INDEX idx_bookings_client ON "Booking"(client_id, datetime DESC);
CREATE INDEX idx_bookings_worker ON "Booking"(worker_id, datetime DESC);
CREATE INDEX idx_services_active ON "Service"(worker_id) WHERE is_active = true;
CREATE INDEX idx_schedules_lookup ON "Schedule"(worker_id, date);
4. Потоки данных (Use Cases)
4.1. Авторизация (единый вход)
Пользователь нажимает кнопку Web App → Telegram открывает URL с query-параметром tgWebAppData.
Frontend извлекает window.Telegram.WebApp.initData — это строка вида query_id=...&user={"id":123...}&auth_date=...&hash=....
Frontend отправляет initData на POST /auth/verify.
Backend воспроизводит HMAC-SHA256:
Секрет = HMAC_SHA256("WebAppData", BOT_TOKEN).
hash должен совпасть с HMAC_SHA256(secret, <все параметры кроме hash, отсортированные>).
Если подпись валидна — извлекается JSON пользователя из поля user.
Если telegram_id новый — INSERT в таблицу users.
Если существует — UPDATE полей username, photo_url (они могли измениться).
Backend генерирует пару JWT:
accessToken (живёт 15 минут) — отправляется в ответе.
refreshToken (живёт 7 дней) — хранится в httpOnly cookie или localStorage (в TMA обычно localStorage, так как cookie не всегда стабильны в WebView).
Frontend сохраняет токен и добавляет в заголовок Authorization: Bearer <token> всех последующих запросов.
4.2. Поиск и геолокация
Получение гео:
Клиент запрашивает navigator.geolocation.getCurrentPosition().
WebView iOS запрашивает разрешение у пользователя один раз.
Если пользователь отказался — показывается поле ручного ввода адреса с геокодером (Яндекс.Карты API или Nominatim).
Запрос на бэкенд: GET /services?lat=55.75&lon=37.61&radius=5&categoryId=3.
Backend:
Если PostGIS: выполняет пространственный запрос.
Если без PostGIS: использует формулу Haversine, но ограничивает выборку «квадратом» (по lat ± radius, lon ± radius) перед дорогим вычислением расстояния.
Frontend:
Показывает список ( дефолт) или точки на карте.
При выборе точки на карте — fitBounds на её координаты.
4.3. Бронирование (Booking Flow)
Это критичная секция, требующая предотвращения race condition.

Пользователь выбирает услугу → открывается экран с календарём.
Загрузка слотов: GET /workers/:id/slots?date=2024-06-15.
Backend берёт шаблон из Schedule на этот день (например, 09:00–18:00).
Вычитает занятые интервалы из Booking со статусом не CANCELLED.
Дробит оставшееся время на слоты длительностью услуги (например, 60 мин).
Пользователь выбирает слот 14:00.
Создание брони: POST /bookings.
Внутри транзакции Prisma:
prisma.$transaction(async (tx) => {
  // 1. Проверить, что слот не занят (SELECT FOR UPDATE)
  // 2. Создать Booking
  // 3. Заблокировать слот (опционально — если слоты материализованы в таблице Slots)
});
Уведомление: Backend кладёт задачу в очередь Redis (BullMQ).
Worker-процесс забирает задачу и вызывает bot.telegram.sendMessage(workerChatId, text).
Для клиента: возвращается статус PENDING. Интерфейс показывает «Ожидает подтверждения мастера».
4.4. Смена статусов брони (State Machine)
[PENDING] ──worker_confirm──► [CONFIRMED] ──service_done──► [COMPLETED] │ │ └──worker_cancel──► [CANCELLED] └──client_cancel──► [CANCELLED]
Изменение статуса — PATCH /bookings/:id/status.
После COMPLETED — клиенту приходит кнопка «Оставить отзыв» (valid 7 дней).
Рейтинг мастера пересчитывается триггером или агрегатом:
UPDATE "WorkerProfile"
SET rating = (SELECT AVG(rating) FROM "Review" WHERE "workerId" = $1),
    "totalOrders" = "totalOrders" + 1
WHERE id = $1;
5. Frontend: детали реализации
5.1. Адаптация под Telegram WebView
Viewport:

<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no" /> — обязательно для iOS, чтобы не было «резинового» зума при тапе.
Нижний padding-bottom должен учитывать tg.safeAreaInset.bottom и tg.contentSafeAreaInset.bottom (для iPhone Dynamic Island и Android Gesture Navigation).
Цвета: Реактивное определение темы:

const tg = window.Telegram.WebApp;
document.body.style.backgroundColor = tg.colorScheme === 'dark' ? '#1c1c1e' : '#ffffff';
В CSS — исключительно CSS-переменные Telegram. Всё, что не покрыто переменными, должно вычисляться из tg.themeParams.

5.2. Навигация и deep linking
В TMA нет адресной строки, но есть tg.initDataUnsafe.start_param.
Если пользователь пришёл по ссылке https://t.me/yourbot?startapp=service_123, то внутри WebApp:
const startParam = tg.initDataUnsafe.start_param; // "service_123"
// React Router делает navigate(`/service/123`);
Кнопка «Поделиться услугой» формирует именно такую ссылку через tg.openTelegramLink или navigator.share.
5.3. Оптимистичный UI (Optimistic Updates)
При бронировании:

Показать спиннер.
Отправить запрос.
Без ожидания ответа сразу показать карточку брони в разделе «Мои записи» со статусом «Ожидается».
Если сервер вернул ошибку (слот заняли раньше) — откатить изменение и показать тост «К сожалению, это время уже занято».
6. Бот и система уведомлений
6.1. Архитектура очереди
Прямой вызов bot.telegram.sendMessage из HTTP-хендлера — плохая практика (задержка ответа, ошибки Telegram блокируют API).

Решение:

HTTP Handler -> Redis (BullMQ) -> Worker (Telegraf) -> Telegram API
При событии (новая бронь) создаётся Job { type: 'NEW_BOOKING', payload: { chatId, serviceName, date } }.
Worker обрабатывает асинхронно.
При ошибке FLOOD_WAIT от Telegram — BullMQ автоматически ретраит с задержкой.
6.2. CRON-напоминания
Redis + node-cron или BullMQ repeatable jobs:

Job ставится при создании CONFIRMED брони.
Время исполнения: bookingDateTime - 24 часа и bookingDateTime - 1 час.
Если бронь отменена — удаляем jobs из очереди по jobId (привязанному к bookingId).
6.3. Интерактивные кнопки в уведомлениях
Для мастера:

bot.telegram.sendMessage(chatId, 'Новая запись!', {
  reply_markup: {
    inline_keyboard: [[
      { text: '✅ Подтвердить', callback_data: `confirm_${bookingId}` },
      { text: '❌ Отклонить', callback_data: `reject_${bookingId}` }
    ]]
  }
});
Обработка callback:

Бот патчит статус через тот же сервисный слой.
Отвечает answerCbQuery.
Редактирует исходное сообщение (editMessageText) — убирает кнопки, добавляет статус.
7. Геолокация: реализация и оптимизация
7.1. Три режима работы
Режим	Описание
GPS	navigator.geolocation → высокая точность, но батарея и разрешения.
IP-Geo	Определение по IP на бэкенде (MaxMind GeoIP2) → фолбэк.
Ручной	Ввод адреса → геокодинг → lat/lon.
7.2. Построение запроса «Рядом»
На больших объёмах (1M+ записей) формула Haversine в ORDER BY — антипаттерн (табличный scan).

Алгоритм с квадратной фильтрацией:

-- Для радиуса 5 км на широте Москвы примерно 0.045 градусов
WHERE lat BETWEEN (:lat - 0.045) AND (:lat + 0.045)
  AND lon BETWEEN (:lon - 0.045) AND (:lon + 0.045)
-- И только потом применяем точную сортировку Haversine на выборке в ~1000 записей
Алгоритм с PostGIS:

WHERE ST_DWithin(
  location::geography,
  ST_SetSRID(ST_MakePoint(:lon, :lat), 4326)::geography,
  :radius_meters
)
ORDER BY location <-> ST_SetSRID(ST_MakePoint(:lon, :lat), 4326);
<-> — оператор «расстояние до» в PostGIS, использует GiST-индекс.

8. Безопасность
8.1. Защита initData
Никогда не доверяйте initDataUnsafe на фронтенде для записи в БД. Всегда валидируйте на бэкенде через HMAC.
Токен бота (BOT_TOKEN) — секрет. Если скомпрометирован — злоумышленник может генерировать валидные initData.
Ротация токена: при смене токена в @BotFather все прошлые сессии станут невалидны.
8.2. JWT и сессии
Access Token хранится в localStorage (TMA ограничен в cookie SameSite).
Refresh Token хранится в IndexedDB с ограниченным сроком жизни.
Middleware на Fastify проверяет Authorization: Bearer и декодирует JWT без обращения к БД (stateless).
8.3. Загрузка фото
Frontend запрашивает GET /upload/presigned с именем файла.
Backend генерирует PUT-presigned URL для S3 (Yandex Cloud / AWS) с ограничением по размеру и Content-Type: image/*.
Frontend загружает файл напрямую в S3 (обходя сервер, экономя трафик).
Backend получает callback/URL и сохраняет в Service.photos.
Валидация:

Максимум 5МБ.
Проверка MIME (file-type или magic number), не доверяйте расширению.
Конвертация в WebP с максимальным разрешением 1920px (через Sharp на Lambda/отдельном микросервисе или presigned + S3 Trigger).

12. Типичные проблемы и решения
Проблема	Причина	Решение
WebView не раскрывается	Не вызван tg.expand() или конфликт с safe_area.	Вызывать tg.ready() перед expand(). Добавить viewport-fit=cover.
InitData невалиден	Тестирование через обычный браузер, а не Telegram.	Использовать Telegram Desktop/Web для разработки.
Дубли бронирований	Race condition на популярном слоте.	SELECT FOR UPDATE в транзакции Prisma или Redis Redlock.
Фото долго грузятся	Загрузка 10MB JPEG.	Sharp/imaginary для resize до 1280px + WebP.
Уведомления не приходят	Bot не может писать пользователю.	Пользователь должен нажать /start у бота хотя бы раз (или это Inline-режим).
Память утекает на сервере	Long Polling + множество соединений.	Переход на Webhook в продакшене.
